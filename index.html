Did that agent session make your codebase better, or quietly worse?

AgentLens snapshots your repository before and after an AI coding agent works, runs your project's own tests, type-checker and linter on both sides, and turns the difference into a 0–100 score you can audit line by line. It runs on your machine and keeps everything in a local SQLite file.

01Problem

Agents write code faster than anyone can review it.

A session ends, the diff looks plausible, and the agent reports that the tests pass. What's missing is a record of how the project's health actually changed, measured the same way every time by the tools the project already trusts.

  • Regressed tests

    Tests that were green now fail, in a module the agent never mentioned touching.

  • Weakened types

    A function that returned int can now return None, and a new helper ships without annotations.

  • Lost coverage

    New branches land untested. Coverage slides two points and nobody notices for a month.

02Method

Measure the repository, not the transcript.

AgentLens doesn't read chat logs or trust the agent's summary of its own work. It compares the code before and after, using the same commands your CI would run.

  1. Snapshot

    Records the base commit and writes a tree of the working copy, uncommitted edits included, through a throwaway git index. Your branch, index and stash are left alone.

  2. Baseline

    Detects the toolchain and runs tests, type-checker and linter before the agent starts, storing pass/fail counts and coverage.

  3. Re-run

    When the session ends, runs the same commands again and stores both phases and the full diff in SQLite.

  4. Score & attribute

    Turns the deltas into a 0–100 score, lists each regression with a severity, and points at the diff hunk most likely responsible.

Toolchain detection

EcosystemDetected fromTestsTypesLint
JavaScript / TypeScript package.json, tsconfig.json, ESLint config vitest run tsc --noEmit eslint .
Python pyproject.toml, setup.py, setup.cfg, requirements.txt, conftest.py pytest + pytest-cov mypy . ruff check .

Missing tools and missing data are never penalised: the score only moves when a check's result differs between baseline and final. Each tool's output goes through a dedicated parser with its own fixtures in the test suite.

Three ways to record a session

agentlens session start|end

Bracket the work by hand. Works with any agent, IDE or chat window.

agentlens run -- <agent>

Wrap a CLI agent: baseline before it starts, finalize when it exits. The agent's exit code passes through.

agentlens watch

Watch the working tree. A session opens on the first change and closes after 45 seconds of quiet.

03Scoring

A score you can recompute by hand.

Every session starts at 100. Each change in a check moves the score by a fixed, documented amount, and the result is clamped to 0–100. There's no model in this number: the same baseline and final results always produce the same score.

SignalRuleDefault
Test regressioneach test that went from passing to failing−15
New failureeach failure beyond the regressed tests−8
Build breakthe suite ran before and can't run now−40
Coverageper percentage point, either direction±0.5
Type errorsper error added or removed∓3
Lint errorsper error added or removed∓1

Regressions are inferred from aggregate counts and only when the suite didn't shrink, so deleting tests isn't mistaken for breaking them. Missing data, such as no coverage report, is skipped rather than penalised.

.agentlens/config.jsonweights are config
{
  "scoring": {
    "test_regression_penalty": 15,
    "new_failure_penalty": 8,
    "build_break_penalty": 40,
    "coverage_delta_weight": 0.5,
    "type_error_delta_weight": 3,
    "lint_error_delta_weight": 1
  },
  "ci": { "min_score": 70 }
}

Override any weight per repository. agentlens score recomputes a stored session with the current weights.

Try the formula

The same arithmetic as src/scoring/score.ts with default weights. The readout uses the CLI's report format.

04Bisection

      

        
When a session spans many commits, name the one that broke it.

        
agentlens bisect binary-searches the session's commits in a separate git worktree, re-running only the check that regressed. Eight commits take three check-runs; a hundred take seven. --retries repeats each probe to guard against flaky tests.

05CI mode

      

        
Gate agent-authored pull requests.

        
agentlens ci scores a pull request against its base branch in an isolated worktree and fails the build when the score drops below --min-score or a critical regression appears. With --comment it keeps one sticky comment on the PR up to date instead of posting a new one on every push.

06Comparison

      

        
Compare agents without fooling yourself.

        
agentlens compare groups sessions by agent and reports the mean, median, spread and a t-based 95% confidence interval. Pairwise comparisons use Welch's t-test, which doesn't assume equal variances, plus Cohen's d for effect size. With fewer than five sessions per agent, it won't call anything significant.

07LLM judge

      

        
An optional judge, measured before it's trusted.

      

    

    

      

        

          
Some qualities don't show up in test counts. agentlens judge asks a model to rate a session's diff, and those ratings are stored separately. They never change the deterministic score.

          
agentlens judge calibrate runs the judge against ten hand-labeled diffs that ship with the tool and reports mean absolute error per dimension and Spearman's ρ against the human labels. You can see how far a given model is off before you rely on it.

          
Off by default. Responses are cached. The provider can be Anthropic's API or any local OpenAI-compatible endpoint, such as Ollama, so diffs never have to leave the machine.

        

        

          
readability
Naming, structure, complexity, and whether intent is obvious.

          
scope_discipline
Whether the change stayed on purpose or wandered into unrelated files.

          
task_match
How completely the diff implements the stated task. Scored only when --task is given.

        

      

    

  







  

    

      
08Local-first

      

        
Nothing leaves your machine unless you send it.

      

    

    

      

        
Storage
One SQLite file, .agentlens/agentlens.db, inside the repository it describes.

        
Configuration
.agentlens/config.json: scoring weights, cost model, CI threshold, judge provider.

        
Dashboard
Served by the CLI on localhost:4319. No account, no sign-in.

        
Network
None by default. The only outbound calls are ones you opt into: the LLM judge, and ci --comment posting to GitHub.

        
Telemetry
None.

        
Cost tracking
Uses real token counts when you pass them (--tokens-in, --tokens-out). Otherwise it estimates from diff size and labels the figure as an estimate.

10Design notes

      

        
Decisions worth defending.

      

    

    

      

        
Deterministic before intelligent
The score is arithmetic over check deltas. The model-based judge reports alongside it and never moves it, so a number in CI means the same thing every time.

        
Your commands, not ours
AgentLens shells out to the test, type and lint tools the project already uses. It measures what your CI measures, with your configuration.

        
Conservative by default
A drop in passing tests counts as a regression only when the suite didn't shrink. Missing tools and missing coverage reports never cost points.

        
Never touch the user's work
Snapshots go through a throwaway git index. CI scoring and bisection run in separate worktrees. AgentLens doesn't commit, reset or stash.

        
Pure cores, thin shells
Scoring, bisection and statistics are pure functions with no I/O. Welch's t-test is checked against textbook values in a suite of more than 250 unit tests.

        
Honest about uncertainty
Estimated costs are labeled as estimates. Comparisons below five sessions are flagged as directional. The judge reports its own error rate.

      

    

  







  

    

      
11Install

      

        
Install from source.

        
AgentLens isn't on npm yet. You need Node 18 or later and git; the host project can be JavaScript, TypeScript or Python.

      

    

    

      

        

          
1 — build and link


$ git clone https://github.com/anonymousz77/AgentLens.git
$ cd AgentLens
$ npm install && npm run build
$ npm link   # puts `agentlens` on your PATH

        

        

          
2 — use it in a project


$ cd ~/code/your-project
$ agentlens init
$ agentlens run --agent claude-code -- claude --print "fix the failing tests"
$ agentlens dashboard

        

      

      
To look around without recording anything, run agentlens dashboard --demo, which serves synthetic data and never touches your database.
